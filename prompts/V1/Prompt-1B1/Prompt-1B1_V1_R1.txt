# PROMPT 1B1 FINAL — SINKRONISASI NASKAH BERSIH, DIALOG, TIMESTAMP, DAN PENGUNCIAN HASIL

KOMPATIBILITAS WORKFLOW: V22.5.1 — Prompt 1B1 membaca dan memperbarui satu DOCX yang sama, lalu mengaudit dominasi narasi, aturan D maksimal 3,00 detik, CAMPURAN aksi-dominan, dan konsistensi hasil Audit Jangkar Aksi Terlewat dari Prompt 1B.
VERSI ATURAN: V20.7 DIPERBARUI DARI V18.7; PROFIL DASAR V12.7

PROFIL DASAR:
- aksi sekitar 45%, jangkar selektif dan ritme padat; Dialog Prompt 2 mengikuti urutan kamera asli tanpa cutaway acak lintas blok, sedangkan Aksi memakai AMBIL–LEWATI dan acak lokal hanya jika aman.
- Jumlah total jangkar tetap mengikuti cerita.
- Narasi wajib menjadi pembawa utama alur.
- Dialog memakai default 1 D per beat; D tambahan hanya bila benar-benar saling membutuhkan; setiap D-xxx maksimal 3,00 detik dan 3 detik bukan target.
- Pengguna mengedit narasi dan dialog pada Naskah Bersih tanpa memperbaiki menit secara manual.
- Kecepatan visual narasi mengikuti Prompt 3 aktif V22.5: `0,50×` tetap default/maksimum dan speed <`0,50×`/intentional freeze tetap boleh bila diperlukan; setiap potongan visual final setelah speed/freeze wajib `2,00–5,00 detik`. Jika pengacakan digunakan, pengacakan hanya boleh antar-shot dari **tempat/lokasi fisik yang sama** dan tetap aman secara kontinuitas. Jika pengacakan tidak dapat dilakukan secara natural/aman, Prompt 3 boleh memakai `MODE DARURAT — TANPA ACAK` tanpa dianggap gagal, selama visual tetap relevan, satu lokasi sesuai frasa, kronologis bila diperlukan, dan batas 2–5 detik tetap terpenuhi.
- MP4 jangkar tetap 1,00× dengan audio asli.

==================================================
TUJUAN UTAMA
==================================================

Prompt 1B1 bertugas:

1. Membandingkan Bagian A teknis asli dengan Bagian B Naskah Bersih hasil edit pengguna di dalam DOCX yang sama. Teks asli setiap unit N/D dibaca dari Bagian A, sehingga tidak diperlukan salinan Naskah Bersih asli dalam file terpisah.
2. Menggunakan teks narasi hasil edit sebagai narasi final.
3. Mendeteksi dialog yang dipertahankan, dipendekkan, dihapus, dipindahkan, atau diganti.
4. Menghapus seluruh metadata dialog yang sudah dihapus.
5. Mencari dialog yang dipertahankan atau diganti melalui SRT dan MP4.
6. Menyesuaikan timestamp awal dan akhir dialog berdasarkan ucapan yang benar-benar tersisa.
7. Menghitung ulang durasi dialog dan jangkar.
8. Mengubah jenis jangkar jika komposisinya berubah.
9. Menghapus jangkar yang tidak lagi memiliki dialog atau aksi yang dipertahankan.
10. Menomori ulang jangkar secara berurutan.
11. Memperbarui seluruh narasi sebelum dan sesudah jangkar berdasarkan naskah hasil edit.
12. Memeriksa kronologi, sebab-akibat, kontinuitas, dan rujukan yang sudah tidak ada.
13. Menguji apakah narasi final tetap membawa alur utama dan tidak bergantung pada dialog panjang.
14. Menguji bahwa setiap D-xxx maksimal 3,00 detik, default satu D per beat diterapkan, dan CAMPURAN tetap aksi-dominan.
15. Memperbarui DOCX yang sama menjadi dokumen final terkunci yang menjadi satu-satunya sumber sah Prompt 1B2 sampai Prompt 5.

Pengguna tidak wajib memperbaiki nomor, menit, timestamp, durasi, jumlah potongan, jenis jangkar, atau posisi timeline.

Gunakan prioritas berikut:

- Bagian A teknis tidak boleh menghidupkan kembali teks yang telah dihapus dari Bagian B Naskah Bersih.

==================================================
SISTEM ID DAN CARA MEMBACA EDIT
==================================================

ID yang digunakan:

- `N-xxx` = unit narasi.
- `D-xxx` = unit dialog.
- `J-xxx` = jangkar.

Aturan pembacaan:

1. ID N atau D ada dan teks sama: `DIPERTAHANKAN`.
2. ID ada dan teks berubah: `DIUBAH` atau `DIPENDEKKAN`.
3. ID yang ada di Bagian A tetapi tidak ada pada Bagian B hasil edit: `DIHAPUS`.
4. ID ada tetapi isi kosong: `DIHAPUS`.
5. ID dipindahkan bersama bloknya: `DIPINDAH`.
6. Teks baru berada di bawah ID lama: `DIGANTI`.
7. ID baru atau teks tanpa ID: cocokkan dengan posisi, isi, dan konteks. Jika aman, buat ID final baru dan laporkan. Jika tidak aman, gunakan `PERLU KONFIRMASI PENGGUNA`.
8. Jika pengguna menggabungkan dua narasi, gunakan teks final persis dari Naskah Bersih dan catat semua ID asal.
9. Jika pengguna menghapus ID tetapi teks masih jelas sama, lakukan pencocokan semantik dan laporkan sebagai `ID HILANG — BERHASIL DICOCOKKAN`.
10. Jangan menganggap metadata lama sebagai bukti bahwa dialog masih dipakai apabila blok D sudah hilang atau kosong.

Aturan keputusan keras:

> Jika dialog ada di Bagian A teknis tetapi ID D atau teksnya tidak lagi ada pada Bagian B Naskah Bersih hasil edit, dialog dianggap sengaja dihapus. Timestamp, durasi, jumlah potongan, rencana MP4, dan seluruh metadata dialog tersebut wajib ikut dihapus atau dihitung ulang.

==================================================
ATURAN NARASI HASIL EDIT
==================================================

Jika narasi diubah:

1. Gunakan teks pengguna sebagai teks utama.
2. Jangan mengembalikan versi lama karena dianggap lebih bagus.
3. Periksa kesesuaian fakta, kronologi, dan sebab-akibat.
4. Perbarui semua kolom `Narasi sebelum adegan`, `Narasi setelah adegan`, dan kalimat pemicu.
5. Perbarui Naskah Bersih Final pada bagian paling bawah DOCX yang sama.
6. Hitung ulang estimasi durasi baca.
7. Jika audio final tersedia, gunakan durasi aktual.
8. Jika audio belum tersedia, gunakan status `DURASI NARASI MENUNGGU AUDIO FINAL`.

Jika narasi dihapus:

1. Hapus unit tersebut dari narasi final.
2. Hapus semua rujukan teknis terhadap ID N itu.
3. Jangan mengubah timestamp sumber jangkar yang tidak berubah.
4. Periksa sambungan dua elemen yang sekarang berdekatan.
5. Jangan menambah narasi baru tanpa izin.
6. Jika sambungan terputus, gunakan status `BELUM AMAN — NARASI PENGHUBUNG HILANG` dan berikan saran minimal terpisah.

Jika narasi digabung atau dipindah:

1. Pertahankan teks dan urutan final sesuai Naskah Bersih.
2. Catat semua ID asal.
3. Perbarui hubungan dengan jangkar di posisi baru.
4. Jangan memindahkan jangkar hanya karena narasi dipindah, kecuali penanda J juga dipindahkan secara sengaja dan konteksnya aman.

==================================================
ATURAN DIALOG DIHAPUS
==================================================

Dialog dianggap dihapus apabila:

- seluruh blok `[DIALOG D-xxx]` hilang;
- blok tetap ada tetapi kosong;
- teks dialog diganti dengan penanda penghapusan yang jelas.

Jika dialog dihapus:

1. Hapus dialog dari naskah final.
2. Hapus timestamp dialog tersebut.
3. Hapus durasi dialog tersebut.
4. Hapus jumlah potongan yang hanya berkaitan dengan dialog itu.
5. Hapus rencana unit JSON dan data subtitle dialog tersebut.
6. Hapus rujukan narasi yang menjadi tidak masuk akal.
7. Jangan mencari dialog pengganti.
8. Jangan mempertahankan metadata lama hanya karena ID J masih ada.
9. Hitung ulang komposisi jangkar.

Perubahan jenis jangkar:

- `DIALOG` tanpa dialog tersisa dan tanpa aksi penting → hapus jangkar.
- `CAMPURAN` setelah semua dialog dihapus tetapi aksi masih dipertahankan → ubah menjadi `AKSI`.
- `CAMPURAN` setelah aksi dibuang tetapi dialog masih dipertahankan → ubah menjadi `DIALOG`.
- `CAMPURAN` dengan sebagian dialog dan aksi masih tersisa → tetap `CAMPURAN`, tetapi jumlah dialog diperbarui.
- Jangkar yang kehilangan semua isi wajib dihapus dan nomor berikutnya diperbarui.

==================================================
ATURAN DIALOG DIPENDEKKAN
==================================================

Jika pengguna menyisakan sebagian dialog:

1. Gunakan hanya teks yang masih ada pada Naskah Bersih.
2. Cari kalimat pertama dan terakhir yang dipertahankan di SRT.
3. Verifikasi batas audio melalui MP4.
4. Pilih awal dan akhir yang natural tanpa memotong kata.
5. Sertakan jeda atau reaksi hanya jika diperlukan agar dialog tidak terasa rusak.
6. Hapus timestamp milik kalimat yang dibuang.
7. Hitung durasi baru hingga dua angka desimal.
8. Perbarui jumlah potongan.
9. Perbarui data subtitle dialog yang akan disimpan di JSON unit.
10. Catat timestamp lama dan baru dalam laporan.

Jika kalimat yang dipertahankan tidak berurutan di sumber:

- jangan memakai satu rentang panjang yang memasukkan kembali dialog yang telah dihapus;
- pecah menjadi beberapa segmen berurutan, misalnya `D-003A` dan `D-003B`;
- setiap segmen memiliki timestamp dan durasi sendiri;
- Prompt 1B2 wajib mencatat pemisahan ini, dan Prompt 2 wajib menerimanya sebagai kebutuhan teknis, bukan dialog baru.

==================================================
ATURAN DIALOG DIGANTI
==================================================

Jika teks di bawah ID D berubah menjadi dialog lain:

1. Cari teks pengganti di SRT.
2. Verifikasi audio dan konteks melalui MP4.
3. Pastikan dialog berasal dari tokoh, lokasi, fase cerita, dan kondisi yang aman.
4. Jika dialog ditemukan dan konteksnya sesuai, ganti teks, timestamp, durasi, sumber, dan hubungan jangkar.
5. Jika dialog ditemukan tetapi berada pada konteks cerita yang berbeda dan akan merusak kronologi, gunakan status `BELUM AMAN — DIALOG PENGGANTI TIDAK SESUAI KONTEKS`.
6. Jika dialog tidak ditemukan, gunakan status `BELUM AMAN — DIALOG PENGGANTI TIDAK DITEMUKAN DALAM SUMBER`.
7. Jangan mengarang timestamp.
8. Jangan mengubah kalimat buatan pengguna menjadi audio dialog asli.
9. Dialog yang tidak ada dalam sumber hanya dapat dijadikan narasi voice-over, dubbing baru, diganti, atau dihapus setelah keputusan pengguna.

==================================================
ATURAN JANGKAR AKSI DAN PENANDA POSISI
==================================================

Penanda jangkar aksi pada Naskah Bersih berfungsi menjaga urutan, bukan sebagai teks narasi.

1. Jika penanda J tetap ada, pertahankan jangkar aksi sesuai Bagian A kecuali ada instruksi penghapusan yang jelas.
2. Jika penanda J tidak sengaja hilang tetapi narasi sebelum dan sesudahnya masih menunjukkan posisi yang sama, jangan langsung menghapus jangkar aksi. Gunakan Bagian A sebagai sumber dan laporkan `PENANDA POSISI HILANG — JANGKAR AKSI DIPERTAHANKAN`.
3. Jika pengguna secara jelas menulis bahwa jangkar aksi dihapus, hapus jangkar dan periksa sambungan.
4. Penghapusan dialog dalam jangkar campuran tidak otomatis menghapus beat aksi.
5. Jangan mencari Jangkar Aksi baru. Audit Jangkar Aksi Terlewat adalah kewenangan Prompt 1B; Prompt 1B1 hanya memverifikasi bahwa hasil 1B konsisten dan tidak kehilangan Jangkar yang sudah dipilih.

==================================================
TIMESTAMP, DURASI, DAN TIGA JENIS WAKTU
==================================================

A. TIMESTAMP SUMBER FILM

- Menunjukkan posisi asli adegan dalam MP4.
- Tidak berubah hanya karena narasi diubah atau dihapus.
- Berubah jika dialog atau rentang adegan dipendekkan, diperpanjang, diganti, atau dipecah.
- Wajib diverifikasi melalui SRT dan MP4.

B. DURASI DIALOG ATAU JANGKAR

- Dihitung dari timestamp sumber final.
- Tidak boleh mempertahankan durasi lama setelah teks dialog berubah.
- Gunakan `durasi = waktu akhir - waktu awal`.

C. POSISI TIMELINE VIDEO FINAL

- Berbeda dari timestamp sumber.
- Bergeser ketika durasi narasi atau jangkar berubah.
- Jika audio narasi final belum tersedia, gunakan `TIMELINE FINAL MENUNGGU AUDIO NARASI`.
- Jangan mengunci estimasi sebagai angka final.

Format timestamp:

`HH:MM:SS.mmm`

==================================================
AUDIT KHUSUS V22.5.1 — DOMINASI NARASI, DIALOG MAKSIMAL 3 DETIK PER D, DAN CAMPURAN AKSI-DOMINAN
==================================================

Prompt 1B1 tidak boleh mengubah pilihan kreatif pengguna secara diam-diam. Namun hasil final hanya dapat dikunci bila keseimbangan berikut lulus:

1. Narasi saja masih menjelaskan kejadian utama, alasan, perubahan konflik, dan akibat.
2. Informasi penting dari dialog yang dihapus tidak ikut hilang dari cerita. Jika pengguna menghapus dialog tanpa menambahkan narasi pengganti dan alur menjadi tidak lengkap, gunakan status `BELUM AMAN — INFORMASI DIALOG HILANG`.
3. Dialog terpilih memberi nilai tambah dan tidak hanya menjadi penjelasan utama yang seharusnya dibawa narator.
4. Default satu D per beat diterapkan terlebih dahulu.
5. D kedua atau D tambahan hanya dipertahankan bila ucapan benar-benar saling membutuhkan dan alasannya dapat dijelaskan.
6. Setiap D-xxx maksimal 3,00 detik. Tiga detik bukan target dan dialog tidak boleh dipanjangkan hanya untuk mengisi batas.
7. Pemotongan D harus menjaga makna utuh dan intonasi natural; jangan memotong kata atau frasa secara kasar.
8. Tidak ada target total 6–10 detik atau batas normal 12 detik per Jangkar. Pengendalian dilakukan per D dan lewat seleksi jumlah D.
9. Untuk CAMPURAN, aksi tetap dominan dan dialog hanya penguat singkat; jangan mengurangi aksi hanya supaya dialog lebih banyak.
10. Tidak ada dua Jangkar Dialog berturut-turut tanpa perkembangan narasi, kecuali masih satu rangkaian yang tidak dapat dipisahkan dan sudah dijelaskan.
11. Narasi tidak mengulang utuh dialog terpilih tepat sebelum dialog diputar.
12. Satu Jangkar mewakili satu beat utama, bukan satu kalimat.
13. Prompt 1B telah menjalankan Audit Jangkar Aksi Terlewat; Prompt 1B1 hanya memastikan Jangkar hasil audit itu tidak hilang atau berubah tanpa alasan pengguna.

Jika pengguna mempertahankan D lebih dari 3,00 detik, Prompt 1B1 tidak boleh menghapusnya diam-diam. Tandai `BELUM AMAN — DIALOG >3 DETIK PERLU KEPUTUSAN PENGGUNA` dan berikan saran minimal untuk memilih frasa yang selesai secara natural.

Jika narasi kurang tetapi pengguna tidak mengizinkan penambahan, jangan menulis narasi baru secara diam-diam. Tandai masalah dan minta keputusan pengguna.

==================================================
AUDIT WAJIB SEBELUM PENGUNCIAN
==================================================

Hasil hanya boleh berstatus siap jika seluruh pemeriksaan berikut lulus:

1. Jumlah blok dialog final sama dengan dialog yang benar-benar masih ada pada Naskah Bersih hasil edit.
2. Tidak ada dialog yang dihapus muncul kembali.
3. Tidak ada timestamp dialog lama tertinggal.
4. Tidak ada durasi lama tertinggal setelah dialog dipendekkan atau diganti.
5. Tidak ada jumlah potongan lama yang salah.
6. Tidak ada jangkar DIALOG tanpa dialog.
7. Tidak ada jangkar CAMPURAN yang masih disebut campuran setelah seluruh dialog atau aksinya hilang.
8. Semua ID N dan D hasil edit telah diproses.
9. Semua ID baru atau hilang telah dijelaskan dalam laporan.
10. Narasi final persis mengikuti hasil edit pengguna, kecuali koreksi minimal yang dilaporkan.
11. Kronologi dan sebab-akibat tetap aman.
12. Tidak ada fakta, motif, emosi, dialog, atau adegan baru yang dikarang.
13. Seluruh timestamp yang berubah telah diverifikasi melalui media.
14. Narasi final dapat dipahami tanpa bergantung pada dialog panjang.
15. Informasi penting dari dialog yang dihapus tetap terwakili atau dinyatakan aman untuk dibuang.
16. Setiap D-xxx maksimal 3,00 detik.
17. Default satu D per beat sudah diuji; setiap D tambahan memiliki alasan kebutuhan langsung.
18. Setiap CAMPURAN tetap aksi-dominan dan tidak berubah menjadi percakapan panjang.
19. Tidak ada pengulangan utuh antara narasi dan dialog terpilih.
20. Tidak ada rangkaian jangkar dialog yang memutus perkembangan narasi tanpa alasan.
21. Tidak ada Jangkar Aksi hasil Audit Jangkar Aksi Terlewat dari Prompt 1B yang hilang tanpa instruksi pengguna.

Jika satu pemeriksaan gagal, jangan mengunci hasil.
